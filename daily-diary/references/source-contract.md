# 资料契约

## 部署配置

在部署的私有本地配置中明确：
工作区、导入目录、日记 Git 仓库、时区、日记主人、直聊 session、
获准的本机/远端来源、采集器、消息通道及接收对象。
不把 IP、SSH 用户、联系人 ID、凭据、聊天或密钥提交进 skill 仓库。

导入目录按日期分开：

```text
diary-import/YYYY-MM-DD/
  manifest.json
  openclaw-weixin-direct.jsonl
  laptop-wechat-history.jsonl
  remotes/<logical-source>/
```

上述两个文件名是当前流程的逻辑名，不要求部署连接名叫 laptop 的机器。
实际连接通过配置映射；不要由旧逻辑名猜 SSH 别名。

## 来源类型

1. 主人与助手的微信直聊：晚间回复、随手记、补充和纠正的权威连续上下文。
2. 本机与获准远端 Codex 会话：只读规范化快照。
3. 本人的微信个人/群聊历史：独立于助手直聊，不能互相冒充。
4. 本人明确提供的旧日记和照片：文风与当天事件的证据。

原始任务 ID 与直聊 session 应保留；不要为了读晚间回复开放所有 agent 的会话。
会话索引轮转或 reset 时，由宿主采集器定位对应直聊族及归档，不让模型猜文件。
归档文件有相邻日期并不代表全部内容属于目标日；按消息时间过滤。
仅以文件修改时间筛选的采集属于候选集，可能漏掉后续更新的旧会话，不应宣称全量完整。

## 时间范围与微信选择

实际生活日优先；未知时按时区使用 05:00 至次日 05:00 的半开窗。
候选文件可扩展到相邻日期，但最终消息归属必须按时间和用户纠正判断。

扫描目标时间窗内所有可用私聊和群聊。
某会话中只要主人至少发送一条消息，保留该会话整个目标窗内的消息用于理解语境。
不使用 Top N、熟人白名单或仅机器人直聊替代完整扫描。
不发言的会话不自动作为个人经历。

## 在线只读与离线后备

当前工作流优先使用固定版本、固定 SHA-256 的 WeArchive 在线只读采集。
运行中已登录的微信可以读取，无需默认退出。
宿主先验证工具哈希和进程，再 capture 完整快照、rebuild 规范化归档。
仅允许查询与读取内存权限；不注入、Hook、结束或重启微信。
读取器和微信版本兼容性是部署时验证项，不能把一次成功推广到所有版本。

capture 完整性需满足 `completeness=complete`、`unavailable=0`、`unsupported=0`。
查询用 SQLite 只读模式并做完整性检查，满足 `truncated=false`、
`failed_conversations=0` 才可报告完整已读。
状态记录扫描/选中会话数、消息数、本人发言数、快照更新时间及本次是否刷新。
完整快照仅证明当时可访问数据库分区完整，不证明客户端从未删减早期记录。

在线工具不可用时才考虑既有离线副本路径。
旧方案若要求退出微信，应说明原因并请用户自行退出，不强制关进程。
复制运行中数据库不自动等于一致快照；必须验证 WAL/分区一致性、解密与时间覆盖。
微信未运行可复用现有完整快照，但时间不足须标记未同步，不启动微信补采。

## manifest 与消息语义

接入器可保留现有 schema，但至少提供目标日期、时区、窗口、各来源状态与计数、
覆盖时间、快照时间、完整性与 warnings。
规范化消息至少保留时间、来源、会话逻辑标识、角色或发件人、是否本人发言、
正文、媒体类型/路径以及能追溯原始资料的定位信息。原始资料不公开。

- `read`：成功读取；记录数和完整性明确。仅完整读取且目标窗内为零才说“无记录”。
- `offline`：连接失败或机器明确离线。
- `not-synchronized`：来源存在，但没有覆盖目标时间窗的可用快照。
- `failed`：采集、解密、解析或完整性验证失败，说明阶段与原因。

读到部分内容时保留已读消息，明确 `completeness=partial` 和 warnings，
不能丢掉已恢复材料，也不能宣称无记录或全量完整。

自动晨间任务只读宿主快照。获准的人工补采使用既有宿主工具，独立处理各来源失败：
微信失效不应阻止 Windows Codex 等其他来源采集。
