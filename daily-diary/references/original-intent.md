# 原始意图

以下是私人工作流设计目标的抽象整理，不包含原始聊天摘录。
这些目标高于后来仅为自动化方便形成的模板。

## 共同完成而非代写报告

用户希望有人帮助回忆、讨论、列举有意思的线索并询问有无补充，
以减少记录中断；资料不足时不应让代理自行编故事。

## 两种记录

工作记录主要从各机器 Codex 会话和微信工作聊天提炼：
真正完成的事情、重要决策、收获、经验、失败教训和未解决项。

个人日记主要从晚间交流、随手记录，以及 Codex/微信中有个人意义的片段提炼：
有趣的事、关系、生活、思考、感受和收获。
工作可以进入日记，但应说明其个人意义，不能再次罗列技术参数。

## 本人的时间和语言

记录实际起床到实际睡觉的一天，过午夜也可属于前一生活日。
采集窗口不是起睡证据。

文风参考优先级：

1. 本人提供的旧日记。
2. 当晚聊天和本人发出的微信消息。
3. 本人确认过的既有成稿。
4. 抽象风格标签，仅作辅助。

没有样本就不能宣称已完全学会个人文风。不要把模型早期生成稿循环当作唯一风格证据。

## 图片、链接和原始材料

尽量使用当天本人发送的相关照片，保留与正文有关的链接和媒体信息。
原始资料只能读和复制；无法读取图片时说明缺口，不猜图注、不用装饰图凑数。
发布照片、链接或他人对话之前检查授权、隐私和接收对象。
