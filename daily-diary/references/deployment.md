# 部署与验收

本文件描述现有方案，不自动修改调度器或服务。

## 连续上下文与调度

当前方案使用 Asia/Shanghai：

| 时间 | 任务 | 目标 |
| --- | --- | --- |
| 09:45 | 宿主素材同步 | 只读采集昨天的各来源并生成 manifest |
| 10:00 | 晨间提要 | 在主人原微信直聊提要、询问补充 |
| 13:00 | 昨日兜底封稿 | 吸收回复；未回复也保留诚实缺口版并归档 |
| 22:00 | 晚间聊天 | 同一直聊回顾当天，不直接生成正式版 |

晨间、晚间和封稿沿用主人现有直聊 session，不另建隔离写作会话。
旧资料中的“晚间隔离 cron”描述不再是当前推荐方式。
采集宿主和写作 agent 分工明确，不以开放跨 agent 会话访问实现连续性。
采集先落可用快照，再逐来源更新；慢媒体源设置时间预算并独立报告缺口。
写作任务不因一个可选来源失败而失去所有已经拿到的资料。
不要把这套具体时间解释成对所有使用者强制要求；更改须按部署授权。

## 发布入口

环境变量：

- `DIARY_REPO`：日记的 Git 仓库绝对路径，必填；不是外层项目仓库。
- `DIARY_PUBLISH`：默认 `0`，仅生成和验证；明确为 `1` 才提交和推送。
- `DIARY_REMOTE`：默认 `origin`。
- `DIARY_BRANCH`：默认 `main`，当前检出分支必须匹配。
- `DIARY_PANDOC`、`DIARY_WEASYPRINT`：可覆盖工具路径，默认从 PATH 查找。
- `DIARY_NOTO_SERIF`、`DIARY_NOTO_SANS`：可覆盖 Noto CJK 字体路径。

发布脚本验证日期、目录、Markdown 与 PDF，
仅提交 `YYYY/MM/YYYY-MM-DD.md`、`.pdf` 和正文实际引用的已验证本地图片，
不上传整个素材目录，保留其他修改和暂存内容。
只推送目标文件生成的提交，不擅自上传之前未推送的无关提交；
若本地 HEAD 不等于已知远端头则停止，要求核查。
已发布且目标文件未改变时不重建 PDF、不重复提交。
推送后核对远端分支提交是否等于本地 HEAD。
PDF 生成成功返回 `validated`，只有真实推送验收成功返回 `published`。
这两种状态都不代表微信送达。

不要 reset、强推、清除用户修改、自动改远端或认证。
同一日并发发布应由调度器串行执行，脚本还使用本地锁避免重入。
已跟踪 PDF 的无变化分支会重新做 PDF 校验，但最终仍需实际查看渲染页。

## PDF 验收

沿用中文 Noto CJK、A4、独立两部分和原有排版。
脚本验证页数、A4、字体嵌入、可提取的中文正文、必需章节及非空渲染。
实际视觉审阅检查乱码、文字溢出、图片和分页；不能把可提取文本等同可读。
本地图片须在源 Markdown 所在目录或其子目录；网络资源默认拒绝，
需要图片时先经授权复制进该目录。

失败停止交付，不静默降级为微信长文字。

## 消息与历史补写

正式版默认短说明 + PDF 附件，仅向已授权的本人直聊发送。
保持发送日志：日期、文件版本/提交、收件人逻辑名、消息 ID、附件状态与时间。
核对实际附件成功状态；任务 `ok`、文本成功或 best-effort 都不是附件送达。
部分失败只重试失败日期；先测试一份、限速，避免连续重复投递。
通道要求新的交互上下文时，请本人发消息刷新，不绕过通道限制。

## 故障分层

1. 原任务是否存在、启用、正确归属，是否已有运行实例。
2. 模型认证与路由：agent 实际认证库、provider、base URL、运行日志。
3. 资料覆盖与完整性：源状态、日期、快照更新时间。
4. 写作与 PDF：必需部分、证据和渲染。
5. Git：目标仓库、精确文件、提交和远端。
6. 微信：附件状态、消息 ID 与接收对象。

多个任务同报 auth 时先查共享认证，不重新创建任务。
先比较 CLI、Gateway 和插件实际版本，旧 CLI 的配置报错不是新版服务的真相。
独立 Codex 登录成功不证明 OpenClaw agent-scoped harness 认证有效。
第三方 provider 的 key 必须对应其正确端点；不要盲目导入到官方端点。
修复前备份、预览迁移并保持配置范围，不把凭据写入输出或仓库。
修后先发不投递的真实模型请求，再按原任务重跑，避免已有运行重复触发。
重跑以当时实际目标日期为准：恢复旧失败日须明确日期，
不能将“昨天”任务直接重跑冒充历史恢复。

## 故障通知与重试

离线聊天副本的网页更新应复用宿主既有采集器：仅允许本人鉴权和显式确认，
通过队列执行，并与日记来源同步互斥。更新前确认聊天客户端已经退出，
无法确认时停止，不自动关闭客户端。副本复制、离线缓存重建和清单扫描应
分别显示进度；复制成功而扫描失败时，保留成功状态，允许单独重扫，
不要把通知投递失败误报为采集失败。网页不得接受任意主机、路径或命令。

长任务应显示排队、采集、复核及生成阶段，并保留刷新页面后的任务身份和
等待时间。仅在分子分母可靠时显示确定进度（如已读会话数/总会话数）；
无法估时的复制或模型调用使用不定进度，不编造百分比。刷新、提交和保存
也应有忙碌及完成反馈，避免重复点击；状态查询中断不自动重提任务。

后台轮询、资料复核待处理和短暂模型拥堵默认只写本地状态，不逐轮推送技术报错。
交付未完成时，通知须说清目标日期、失败阶段、已有成果是否可用及具体下一步，
不将内部路径或异常堆栈当作用户提示；同日同类问题合并并限频。
扫描、成稿、归档和通知发送分别记录状态，通知失败不应被误报为扫描失败。
确定已终止的临时模型失败可限次退避重试；提交或发送结果未知时先核对，不能盲目重试。
需要修改正文的格式问题转为待修订状态，保留草稿，不在每次发布轮询中重复失败。

## Skill 维护

区分通用仓库、安装副本和个性化部署规则，列清实际生效入口，不假设它们自动同步。
维护部署时，把可复用改进在同一轮脱敏移入通用仓库，测试并核对远端提交。
不要整目录覆盖个性化版本；联系人、健康数据、私人聊天、真实日记、主机地址和凭据留在私有配置。
没有明确发布授权时仅准备差异并说明未推送；已有授权下也只提交对应变更，不强推。
本仓库不是宿主采集服务的完整备份；宿主专用代码仍由各部署维护。
